# Contributing

Use GitHub's native collaboration surfaces so project history stays discoverable and does not split across duplicate documents.

- Report reproducible defects with the Bug Report form.
- Track approved or otherwise well-defined work with the Implementation form.
- Propose project changes in the native Ideas Discussion category when Discussions are enabled. Significant technical changes should be approved there before implementation.
- Keep pull requests focused, link the relevant Issue or approved Ideas Discussion, and describe verification and material risks.
- Prefer short-lived task branches and Conventional Commits.

Before contributing, read the repository README and any repository-specific `AGENTS.md`. Project-specific commands, architecture constraints, security reporting, licensing, and release rules belong in the individual repository and override this generic baseline.

Never include credentials, tokens, private keys, production data, or other sensitive information in Issues, Discussions, pull requests, commits, or logs.
